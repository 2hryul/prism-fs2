# 개발노트 — 주석검색 임베딩 차원 불일치(512↔768) 진단·하드닝

## 2026-06-10 11:20 작업 내역

- **증상**: 주석검색 실행 시 500 — `ValueError: shapes (512,) and (768,) not aligned`. (`POST /api/compare` 500)
- **원인 (재현·확인)**:
  - 검색 인덱스는 **768차원**(ko-sroberta `jhgan/ko-sroberta-multitask`)으로 생성됨(실측: `src/storage/library/KB/2025Q2/index.json` dim=768).
  - 에러를 낸 8021 서버는 **임베딩 모델 로드 실패 → bigram 폴백(512)** 상태. `make_embedding`이 모델 실패 시 **조용히** 512 벡터를 반환(`app.py` line 412~418) → 768 인덱스와 `np.dot` 시 shape 불일치.
  - 빌드한 `setup_v0.2.0.exe` 자체는 **동봉 모델 768 정상 로드**(스모크 로그: `embedding backend: local model (..._internal\models\ko-sroberta)`). 즉 에러원은 exe가 아니라 **8021을 선점한 별도 서버(bigram)**. exe는 포트 충돌(`[Errno 10048]`)로 기동 실패 → 브라우저가 좀비 서버에 붙어 검색 → 512/768 충돌(추정 시나리오, 정황 일치).
- **수정 (하드닝 — 조용한 폴백 → 명확한 안내)**: `src/app.py`
  - `EMBED_DIM` 상수(로컬 모델 768 / bigram 512) 추가.
  - `_value_error_handler` 추가 — shape 불일치 ValueError를 **503 + 원인·조치 안내**(모델 로드 실패/모델 동봉 exe 실행/모델 경로 확인)로 변환. 그 외 ValueError는 **내부 구조 비노출 일반 500**(보안 규칙: 스택·경로 노출 금지).
  - `_sample_index_dim()` + lifespan 기동 시 **선제 경고**: bigram 백엔드인데 인덱스가 768이면 `[CRITICAL]` 로그.
