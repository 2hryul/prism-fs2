# 개발노트 — 연결/별도 재무제표 본문 전체 인덱싱

## 2026-06-17 작업 내역

### 작업 내용
연결재무제표(`review`)·별도재무제표(`review_sep`) PDF의 **전체 본문(주석 포함)** 을 검색 인덱싱(v0.9.2 → 0.10.0). 기존엔 PDF에서 주석(footnotes)만 추출·인덱싱돼, 감사의견·재무제표 본표 등 비주석 본문은 검색되지 않았음. 사용자 요청: 재무수치(fs_structured)와 별개로 본문 내용도 검색 가능하게.

**범위 확정**: 사업보고서(report) 제외 — 연결/별도 재무제표 두 문서만. "본문"=PDF 전체(주석 포함). 새 문서 수집 없음(기존 PDF 재인덱싱).

### 변경 파일
- **`src/app.py`**:
  - `body_index_path()`·`build_body_index()`(신규): PDF 전 페이지를 **페이지 단위 본문 유닛**(`no="B{p}"`, `title="본문 p.N"`, fs_div=문서기본)으로 청킹·임베딩 → `index_body_{dt}.json`. 청크/임베딩은 기존 `_chunk_text`(schema 4)·`make_embeddings`·`_round_emb` 재사용. 페이지당 6청크·문서당 4000청크 상한.
  - `index_entry`: 주석 인덱싱 후 `build_body_index` 자동 호출(실패해도 주석 검색 유지). INDEX_STATUS에 `body_pages` 추가.
  - `_load_body_index()`(신규). `/api/notes/rag`: `include_body=True` 파라미터 추가 — 본문 유닛을 주석 인덱스에 병합해 retrieve(감사의견·본표 등 검색).
- **`src/static/index.html`**: RAG 출처 칩에서 본문 유닛(`no="B…"`)을 **📄 본문 pN**(청록색)으로 구분 표시. 인라인 미리보기·하이라이트는 기존 경로 그대로.
- **데이터**: `reindex_all.py --no-llm`로 21개 review/review_sep 셀 재인덱싱 → `index_body_*.json` 생성(신한 2025FY 연결 333페이지·13.8MB 등).
- **`VERSION`** 0.9.2 → 0.10.0.

### 결정 사항
- **별도 인덱스 파일**: 주석 인덱스(`index_{dt}.json`)는 제목 정밀검색용으로 유지, 본문은 `index_body_{dt}.json`로 분리. 질의 시 병합. 주석/본문 일부 중복은 사용자 동의(전체 검색 우선).
- **백엔드만 + 재인덱싱**: collect_dart·report·VALID_DOC_TYPES 변경 없음. fs_structured(재무수치)와 무관.
- **fs_div**: 본문 유닛 fs_div=문서기본(review→연결, review_sep→별도)로 RAG fs_div 필터 통과.
