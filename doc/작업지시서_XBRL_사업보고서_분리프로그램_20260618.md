> **개선 이식 출처 = prism-fs `8e77ce5`** (`D:\SOURCE\prism-fs`) — 이번 세션 개선은 v0.4.0엔 없으므로 여기서 가져온다.

2. **prism-fs `8e77ce5`에서 이식**: §2의 검색·UX·측정 개선 전부(v0.4.0 베이스엔 부재). 동일 파일(`app.py`·`notes_rag.py`·`static/index.html` 등)의 해당 부분을 베이스 위에 덮어/병합.

## 0. 배경·목적

- prism-fs는 v0.4.0(`c6f4c87`)에서 **사업보고서(report)·연간(FY) 본문·XBRL을 전면 제거**하고 "연결/별도 재무제표 + 주석 검색"의 슬림 앱으로 정리됨.
- 제거된 XBRL·사업보고서 처리는 **무겁고 성격이 달라**(원문 XBRL 파싱·태깅 진단·RDF 온톨로지·사업보고서 본문 섹션) prism-fs에 다시 넣지 않기로 함.
- 따라서 **별도 프로그램**(가칭 `prism-xbrl`)으로 분리 구현한다. 단, **검색 정확도·UX는 prism-fs에서 이번 세션에 끌어올린 수준을 그대로 계승**해야 한다(원점에서 다시 만들지 말 것).

### 운영 형태
- **베이스 = 별도 구성한 v0.4.0 repo**(이 repo에서 작업·커밋). 독립 FastAPI 서버(**포트 8022** 권장 — prism-fs 8021과 충돌 방지), 독립 PyInstaller onedir 빌드.
- prism-fs 런타임 의존 없음(개선 코드는 `8e77ce5`에서 복사/이식). 임베딩 모델 동일(`jhgan/ko-sroberta-multitask`) 동봉.
- 데이터 저장 구조는 v0.4.0 베이스의 라이브러리 모델 그대로: `storage/library/{회사}/{기간}/...`.

## 2. 필수 계승 — prism-fs 이번 세션 개선 전체

신규 프로그램은 아래를 **모두 포함**해야 한다. 각 항목의 구현은 현 prism-fs(`8e77ce5`)에서 이식하고, 출처 개발노트를 참조한다.

### 2-1. 검색 정확도 (핵심)
- **문장경계 청크(index schema 4)** — `src/app.py` `_chunk_text`/`_split_sentences`(`_SENT_SPLIT_RE`). 문장 중간 절단 제거. [doc/개발노트_검색튜닝_PDF하이라이트_20260617.md]
- **전체 본문 인덱싱** — `build_body_index`/`body_index_path`/`_load_body_index` → `index_body_{doc}.json`. PDF 전 페이지를 페이지 유닛(`no="B…"`)으로 청킹·임베딩. RAG 병합. [doc/개발노트_본문전체인덱싱_20260617.md]
- **주석 우선 정렬(본문 강등)** — `src/notes_rag.py` `retrieve()` 정렬에서 본문 유닛에 `BODY_RANK_PENALTY=0.15` 강등. **제목검색 MRR 0.667→0.813 회복**(증거: `scripts/eval_search.py`). [handoff/REVIEW-REQUEST.md, BUILD-LOG.md Step S1]
- **하이브리드 랭킹**: 코사인 0.7 + BM25 0.3, kiwi 형태소, 동의어 확장(`synonyms.py`, 32그룹), IDF 제목 보너스 — 기존 prism-fs `notes_rag.retrieve` 그대로.
- 사업보고서 적용: report 본문(섹션 + 전체 본문) + XBRL 라벨 텍스트를 동일 파이프라인으로 인덱싱.

### 2-2. 화면·UX
- **PDF 원문 매칭 하이라이트** — pdf.js 4.0 `renderTextLayer`로 텍스트레이어 오버레이, 질의어 `<mark>` 형광 + 매칭 페이지 자동 스크롤. 캔버스를 컨테이너 폭에 맞춰 렌더(정렬). `renderPdfRange(terms, focusPage)`. [개발노트_검색튜닝_PDF하이라이트]
- **PDF 더블클릭 원문 새 창** — dblclick 핸들러는 `pageWrap`에 부착(텍스트레이어가 가로채지 않게). [개발노트_업로드검증_PDF더블클릭_매트릭스]
- **다 대상 나란히 비교**(계정/항목=행, 대상=열) + 전체폭(`*-wide` body class) + **좌측 컬럼 sticky** + 긴 id 줄바꿈. XBRL 4사 계정 비교에 그대로 적용. [개발노트_재무제표비교_4사동시표시]
- **검색 후보 접기** — 패널별 "나머지 N개 접기/펼치기"(`.cand-list.collapsed`). [개발노트_비교조회_후보접기]
- **대상 칩 드래그&드롭 정렬** — `draggable` 칩 재배열 → 표시 순서 반영. [개발노트_타이틀변경_RAG선택검색_비교정렬DnD]
- **선택 문서만 검색** — RAG가 라이브러리 선택 셀(`cell_keys`, 연결/별도/문서유형 혼재)만 조회. 출처별 `doc_type` 표기. [동 개발노트]
- **업로드 기간 자동검증** — `detect_period_from_text`가 **결산기준일(YYYY년 M월 DD일)**로 Q1/Q2/Q3/FY 식별, 선택과 불일치 시 경고·자동채움. [개발노트_업로드검증]
- **기간(컬럼) 헤더 클릭 = 대상 일괄 삭제**(확인 후). [개발노트_기간일괄추가삭제]
- **초보 안내**: 라이브러리 3단계 퀵스타트 + **전 탭 닫기 가능 가이드**(`.tab-guide`/`dismissGuide`/localStorage). [개발노트_초보안내_3탭테스트, 가이드닫기수정_전탭안내]
- **출처 구분 칩**: 주석 vs 본문(`📄 본문 pN`) 시각 구분.

### 2-3. 측정·품질 게이트
- **골든셋 평가 하니스** — `scripts/eval_search.py`(hit@k·MRR·동의어 프로브) 이식. XBRL/사업보고서용 골든셋(`golden_search.json`/`golden_queries.json`) 신규 작성.
- **빌드 게이트** — `build.ps1` 패턴: pytest 통과 + 외부 https 0(폐쇄망) + PyInstaller onedir + 모델/데이터 동봉. VERSION 파일 단일 관리.

## 3. 단계별 작업 순서 (STEP)

> 한 STEP 완료·검증 후 다음 진행. prism-fs의 Architect/Builder/Reviewer 핸드오프 패턴(`handoff/`) 권장.

- **STEP 0 — 베이스 확인 + 개선 이식 준비**: **별도 v0.4.0 repo에서 작업 시작**(앱 골격 이미 존재). 포트 8022로 변경(`run_server.py`), `build.ps1`/spec 이름 정리, VERSION 재설정(예: 0.1.0). 이어서 prism-fs `8e77ce5`의 §2 개선을 이식할 대상 파일을 식별 — `src/app.py`(청크·본문인덱싱·업로드검증·엔드포인트), `src/notes_rag.py`(주석우선 정렬), `src/static/index.html`(PDF 하이라이트·나란히 비교·후보접기·드래그·가이드·cell_keys), `scripts/eval_search.py`, `synonyms*.py`. **diff 단위로 베이스에 병합**(v0.4.0과 8e77ce5의 동일 파일 차이를 적용).
- **STEP 1 — 수집(collect)**: `collect_dart.py`에서 report 본문 PDF + XBRL(`fnlttXbrl`) 수집 복원(git `c6f4c87^`). 산출: `report.pdf`, `xbrl/` 해제물.
- **STEP 2 — XBRL 태깅 엔진**: `xbrl_tagging.py`(708줄)·`build_xbrl_tagging.py`·테스트 이식. `/api/xbrl-tagging`·`/matrix` 복원. L2 차원 인지 포함.
- **STEP 3 — 사업보고서 본문 인덱싱**: `sections.py` 복원 + STEP 2-1의 **문장경계 청크·전체 본문 인덱싱·주석 우선 정렬**을 결합. report 본문 섹션 + 주석 + XBRL 라벨을 검색 인덱스로.
- **STEP 4 — 계정↔주석 링크**: `build_xbrl_links` 복원 + 임베딩 매칭.
- **STEP 5 — UI**: §2-2 UX 전부 적용(PDF 하이라이트·더블클릭·나란히 비교·후보접기·드래그정렬·가이드·업로드검증). XBRL 태깅 매트릭스 탭 + 사업보고서 본문/주석 검색 탭 + (선택)RDF 온톨로지 그래프(`xbrl_rdf_export_graph.html` 통합).
- **STEP 6 — 측정**: 골든셋 작성 + `eval_search.py`로 MRR 기준선 측정·기록.
- **STEP 7 — 빌드/배포**: `build.ps1`로 onedir 번들 + frozen 스모크(서버 기동·헬스·데이터 서빙). `dist/setup/setup_v{VERSION}/`.

## 6. 비포함·주의
- prism-fs는 **건드리지 않는다**(별도 프로그램). 두 앱은 데이터 폴더·포트를 분리.
- `.env`·`storage/`·`dist/`는 gitignore. 시크릿 하드코딩 금지.
- 온톨로지·Graph-RAG '데모'(prism-fs에서 제거됨, `개발노트_온톨로지제거_20260617.md`)는 더미였음 — 본 프로그램에서 XBRL→RDF 그래프를 **실데이터로** 제대로 구현할지는 STEP 5에서 결정.
- 이 세션 변경 중 **재무제표 비교(fs) 탭·FY 다년 시계열**은 prism-fs 고유(재무수치)라 본 프로그램 필수 아님 — 단 "다 대상 나란히 비교" 레이아웃 패턴은 XBRL 계정 비교에 재사용.
