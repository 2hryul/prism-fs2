# 개발노트 — 검색 정확도 튜닝 + PDF 원문 매칭 하이라이트

## 2026-06-17 작업 내역

### 작업 내용
세션 목표 "PDF 내용의 정확한 검색 + 사용자 편의"에 따라 두 가지를 구현(v0.5.0 → 0.6.0).
1. **검색 튜닝**: 청크를 250자 raw 슬라이스 → **문장 경계 패킹**으로 전환(문장 중간 절단 제거 → 임베딩/스니펫 품질↑). 스키마 v3 → v4.
2. **PDF 원문 매칭 하이라이트**: 검색 결과 클릭 시 인라인 PDF 미리보기에 pdf.js 텍스트 레이어를 깔고 질의어를 형광(`<mark>`) 표시 + 매칭 페이지 자동 스크롤. 비교조회·RAG 양쪽 적용.

### 변경 파일
- **`src/app.py`**: `_chunk_text` 문장경계 그리디 패킹으로 교체(`_SENT_SPLIT_RE`·`_split_sentences` 추가, 초장문 문장만 문자 슬라이싱 폴백). `INDEX_SCHEMA` 3→4.
- **`src/static/index.html`**:
  - CSS: `.pdf-page`(relative), pdf.js 표준 `.textLayer`(투명 오버레이) + `.textLayer mark`(노란 형광).
  - `termsFromQuery`·`addTextLayerHighlight`(신규): `pdfjsLib.renderTextLayer({textContentSource,container,viewport}).promise` 로 텍스트 레이어 렌더 후 질의어 `<mark>` 래핑, 첫 매칭 스크롤.
  - `renderPdfRange` 개편: 캔버스를 컨테이너 폭에 맞춰 렌더(CSS 재스케일 회피 → 텍스트레이어 정렬), `terms`·`focusPage` 인자 추가.
  - 비교조회: `COMPARE_TERMS`(질의어) 저장, `selectCandidate`가 `match_page`로 스크롤·하이라이트.
  - RAG: `ragPreview`(신규)로 출처 클릭 시 하단 인라인 미리보기 렌더(terms=d.terms), "↗" 원본 새 창 보조 링크.
- **테스트**: `test_index_schema3.py` — 스키마 4 갱신, 문장경계 청크 3종(경계 분할·한도 패킹·초장문 폴백)으로 재작성.
- **데이터**: 18개 review/review_sep 셀 schema v4 재인덱싱(`reindex_all.py --no-llm`).
- **`VERSION`** 0.5.0 → 0.6.0.

### 결정 사항
- **pdf.js 4.0.379는 `TextLayer` 클래스 미export, `renderTextLayer` 함수만 export** → 후자로 구현. `--scale-factor` CSS 변수 필수(스팬 위치 계산).
- **텍스트레이어 정렬**: 기존 `canvas{width:100%}` CSS 재스케일은 텍스트레이어와 어긋나므로, 캔버스를 컨테이너 폭(px)에 맞춰 렌더하고 `.pdf-page` 폭=viewport 폭으로 1:1 정렬.
- **RAG 하이라이트**: 출처가 새 창(네이티브 뷰어)이라 주입 불가 → 인라인 미리보기 패널로 전환해 동일 헬퍼 적용.
- **검증**: 사용자 선택대로 **브라우저 수동 확인**(골든셋 자동측정 생략). 동의어는 32그룹 이미 충실 → 신규 추가 없음.
